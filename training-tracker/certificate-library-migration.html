Move Certificates Out Of TT TrainingRecords Attachments

This is the separate fix guide for moving certificates into a locked SharePoint document library while leaving the training tracker metadata in the existing lists. Follow the test phase first. Do not remove old attachments, flows, or formulas until the new save and email flows work against one real test record.

Answer to the big question: yes, you can test this in advance. Build the new TT Certificates_LTD library, optionally rename its display name to TT Certificates (LTD), and build the two new TEST flows first. Add two temporary buttons on scrCourseDetail to call those test flows. If the test works, then do the cutover edits. If it does not, delete the test buttons and the current app keeps using the old attachment route.

1. What Changes And What Stays

AreaKeepChange
Existing SharePoint lists TT Personnel, TT Courses, TT TrainingRecords, TT AuditLog, TT ComplianceSnapshots Add a separate document library created as TT Certificates_LTD. You can rename the display name to TT Certificates (LTD) afterwards, but Power Automate may still show/use the original internal library name.
Training record metadata DateCompleted, UploadedByEmail, LastUpdatedByEmail, LastUpdatedOn, LastStatus, compliance maths, admin dashboard, audit log. The record no longer needs a SharePoint list attachment to prove a certificate exists. The file is stored in TT Certificates_LTD / TT Certificates (LTD) instead.
Power Apps file picker The existing unbound Attachments@2.3.0 control and colNewCertificate staging pattern. The save button calls a new library flow instead of the old attachment flow.
Power Automate The old flows stay untouched during testing. New flows write/read the locked document library. The read flow emails the certificate instead of returning base64 to Power Apps.
Security Users still use the app to see their training data. Only admins/service account have direct access to TT Certificates_LTD. Normal users do not browse the certificate library.
Important: SharePoint document libraries and columns have internal names. Create the library first as TT Certificates_LTD. If you then rename the display name to TT Certificates (LTD), Power Automate may still show or require the original internal name/path. Create the columns below with the exact names shown, with no spaces.

2. Create The New SharePoint Document Library

  1. Open the same SharePoint site that contains the Training Tracker lists.
  2. Create a new Document library, not a normal list. Name it exactly TT Certificates_LTD.
  3. After creation, you may rename the display name to TT Certificates (LTD) if policy needs that wording. Do not recreate it just for the display name. The original internal path/name is the useful stable bit for Power Automate.
  4. In the new library, add the columns below.
Column nameTypeRequired?Purpose
TrainingRecordIDNumberYesLinks the file back to TT TrainingRecords.ID.
PersonEmailSingle line of textYesThe person who owns the training record.
CourseIDNumberNoThe course ID from TT Courses.
CourseNameSingle line of textNoReadable course name for admin/search/audit.
DateCompletedDate and time, Date onlyNoThe completion date saved on the training record.
UploadedByEmailSingle line of textNoThe app user who uploaded or replaced the file.
UploadedOnDate and time, Date and timeNoWhen the library copy was created.
IsCurrentYes/NoNoUse Yes. Kept for future-proofing if you ever keep old versions.

Permissions For Testing

For the first test, do not lock the library down yet. Give yourself and the flow owner access. Once the test flow works, change permissions like this:

  • Stop inheriting permissions on TT Certificates_LTD / TT Certificates (LTD).
  • Keep Full Control for the site owners/admins who are allowed to inspect certificates.
  • Keep access for the account whose SharePoint connection the flows use.
  • Remove normal app users from this library only. Do not remove their access from the metadata lists yet.

Confirmed shortcut: paste these two actions directly under the trigger, before any SharePoint action. Paste varSuccess first, then varMessage.

Actions

  1. SharePoint - Get item. Site: your Training Tracker site. List: TT TrainingRecords. Id: dynamic content RecordID.
  2. Condition - Authorised? Use OR logic:
    PersonEmail from Get item is equal to trigger ActorEmail
    OR trigger IsAdmin is equal to expression true.
    Use the expression editor for true, not a Yes/No dropdown.
  3. Inside If no: set varSuccess to expression false. Set varMessage to You are not authorized to save this certificate.
  4. Inside If yes: add a nested Condition - Has file?. Compare trigger HasNewFile to expression true.
  5. Inside Has file? If yes: add SharePoint - Get files (properties only). Site: same site. Library: select TT Certificates_LTD or the renamed display value TT Certificates (LTD), whichever Power Automate shows. Filter Query:
    OData Filter Query
    TrainingRecordID eq [RecordID dynamic content]
    Do not type the square brackets. Type TrainingRecordID eq , then insert the real RecordID token from the dynamic-content picker.
  6. Still inside Has file? If yes: add Apply to each over the value from Get files (properties only). Inside it, add SharePoint - Delete file. File Identifier: use the current item's Identifier dynamic content.
  7. Still inside Has file? If yes, but below the delete loop: add SharePoint - Create file. Site: same site. Folder Path: use the folder/library path Power Automate offers for the certificate library, normally /TT Certificates_LTD even if the display name has been renamed. File Name: insert dynamic content RecordID, then type a hyphen, then insert dynamic content FileName. File Content: choose FileContent contentBytes, not FileContent name.
  8. Below Create file, add SharePoint - Update file properties. Library: select TT Certificates_LTD / TT Certificates (LTD). Id: use ItemId from Create file. Set the properties:
    PropertyValue
    TitleCourseName
    TrainingRecordIDRecordID
    PersonEmailPersonEmail
    CourseIDCourseID
    CourseNameCourseName
    DateCompletedDateCompleted
    UploadedByEmailActorEmail
    UploadedOnexpression utcNow()
    IsCurrentexpression true
  9. Still inside the authorised branch, after the nested file condition: add SharePoint - Update item for TT TrainingRecords. Id: RecordID. Re-supply the required fields and set:
    FieldValue
    PersonEmailPersonEmail
    CourseIDCourseID
    CourseNameCourseName
    DateCompletedDateCompleted
    UploadedByEmailActorEmail if a manager/admin uploaded it; leave blank if you want to keep the current simplified behaviour.
    LastUpdatedByEmailActorEmail
    LastUpdatedOnexpression utcNow()
    LastStatusCertificate saved
  10. Still inside authorised branch: create the same TT AuditLog row the old save flow created. EventType: Certificate saved. PersonEmail: PersonEmail. CourseID: CourseID. ActorEmail: ActorEmail. EventDate: utcNow().
  11. Still inside authorised branch: set varSuccess to expression true. Set varMessage to OK.
  12. After the whole authorisation Condition, outside both branches, add exactly one Respond to a PowerApp or flow action. Outputs:
    Yes/No success = varSuccess
    Text message = varMessage

This replaces the base64 download flow. It avoids the broken four-field response schema entirely. The app asks for the certificate, the flow checks authorisation, and the flow emails the file to the authorised requester.

Top-Level Variables

NameTypeInitial value
varSuccessBooleanempty

Confirmed shortcut: use the same two variable initializer buttons here as well. Paste varSuccess first, then varMessage, directly under the email trigger.

Actions

  1. SharePoint - Get item. List: TT TrainingRecords. Id: RecordID.
  2. Condition - Authorised? Same as the save flow:
    record PersonEmail equals trigger ActorEmail
    OR trigger IsAdmin equals expression true.
  3. Inside If no: set varSuccess to expression false. Set varMessage to You are not authorized to view this certificate.
  4. Inside If yes: add SharePoint - Get files (properties only). Library: select TT Certificates_LTD / TT Certificates (LTD). Filter Query: TrainingRecordID eq followed by dynamic content RecordID. Top Count: 1.
  5. Add a Condition - Found certificate?. Left side expression:
    Expression
    length(body('Get_files_(properties_only)')?['value'])
    is greater than 0.
  6. Inside Found certificate? If no: set varSuccess to expression false. Set varMessage to No certificate is on file for this record.
  7. Inside Found certificate? If yes: add Apply to each over the value from Get files (properties only). This loop should run once because Top Count is 1.
  8. Inside that loop: add SharePoint - Get file content. File Identifier: current item Identifier.
  9. Inside that loop: add Office 365 Outlook - Send an email (V2).
    FieldValue
    ToActorEmail
    SubjectYour Training Tracker certificate
    BodyYour requested certificate is attached.
    Attachments Namecurrent item File name with extension, or Name if that is what your picker shows.
    Attachments ContentGet file content file content/body.
  10. Still inside Found certificate? If yes, after the loop: set varSuccess to expression true. Set varMessage to Certificate emailed to you.
  11. After the whole authorisation Condition, outside both branches, add exactly one Respond to a PowerApp or flow. Outputs:
    Yes/No success = varSuccess
    Text message = varMessage

5. Add Temporary Test Buttons In Power Apps

This is how you test without breaking the current working screen. Add the two test flows as data sources. Do not remove the old flows yet.

Temporary Save Test Button

Add a small temporary button to scrCourseDetail, or reuse an unused test button if you already have one. Set its Text to TEST save library and its OnSelect to this:

Power Fx - temporary save test
=Set(
    varSaveResult,
    'TT - Save Certificate Library TEST'.Run(
        datCompletion.SelectedDate,
        CountRows(colNewCertificate) > 0,
        If(CountRows(colNewCertificate) > 0, First(colNewCertificate).Name, ""),
        If(CountRows(colNewCertificate) > 0, First(colNewCertificate), Blank()),
        Lower(varRecord.PersonEmail),
        varCourse.CourseName,
        varMyEmail,
        varViewingForSelf,
        varRecord.ID,
        varCourse.CourseID,
        varIsAdmin
    )
);
If(
    varSaveResult.success,
    Notify("TEST save worked. Check TT Certificates (LTD).", NotificationType.Success),
    Notify(varSaveResult.message, NotificationType.Error)
)

Temporary Email Test Button

Add a second temporary button. Set its Text to TEST email cert and its OnSelect to this:

Power Fx - temporary email test
=Set(
    varCertEmailResult,
    'TT - Email Certificate Library TEST'.Run(varRecord.ID, varMyEmail, varIsAdmin)
);
If(
    varCertEmailResult.success,
    Notify(varCertEmailResult.message, NotificationType.Success),
    Notify(varCertEmailResult.message, NotificationType.Error)
)

Safe Test Script

  1. Pick one training record you can safely test with.
  2. Open that record in scrCourseDetail.
  3. Select a small PDF or image certificate using the existing file picker.
  4. Click TEST save library.
  5. Open SharePoint TT Certificates_LTD / TT Certificates (LTD). Confirm one file exists for that TrainingRecordID and its metadata columns are filled.
  6. Click TEST email cert.
  7. Confirm the email arrives and the attachment opens.
  8. Run the test again with a different file. Confirm the library still has one current file for that TrainingRecordID, not duplicates.
Stop here if the test fails. Do not edit the live save/open buttons yet. The existing app can keep using the old list attachments while the new flows are fixed.

6. Cutover After The Test Passes

Only do this section after the test save and test email both work.

Rename Or Recreate Final Flows

You can either rename the two test flows after they work, or create final clean copies manually. Recommended final names:

  • TT - Save Certificate Library
  • TT - Email Certificate Library

If you rename the test flows, remove and re-add them in Power Apps afterwards so the data source names are refreshed.

Update btnSaveCert.OnSelect

Replace only the flow call name. The arguments stay the same.

Power Fx - new live save call
'TT - Save Certificate Library'.Run(
    datCompletion.SelectedDate,
    CountRows(colNewCertificate) > 0,
    If(CountRows(colNewCertificate) > 0, First(colNewCertificate).Name, ""),
    If(CountRows(colNewCertificate) > 0, First(colNewCertificate), Blank()),
    Lower(varRecord.PersonEmail),
    varCourse.CourseName,
    varMyEmail,
    varViewingForSelf,
    varRecord.ID,
    varCourse.CourseID,
    varIsAdmin
)

In the full existing formula, this replaces the old 'TT - Save Certificate'.Run(...) call inside IfError. Keep the surrounding busy/error/notify code.

Update btnOpenCertificate

The old button tries to launch base64 returned by TT - Get Certificate. Replace that behaviour with an email request.

PropertyNew value
Text="Email certificate"
Visible=!IsBlank(varRecord) && !IsBlank(varRecord.DateCompleted)
Power Fx - btnOpenCertificate.OnSelect
=Set(varCertError, "");
Set(varCertStatusText, "Requesting certificate email...");
Set(varCertBusy, true);
Set(
    varCertEmailResult,
    IfError(
        'TT - Email Certificate Library'.Run(varRecord.ID, varMyEmail, varIsAdmin),
        {success: false, message: "Flow could not be reached. Check your connection and try again."}
    )
);
Set(varCertBusy, false);
If(
    varCertEmailResult.success,
    Set(varCertStatusText, ""); Notify(varCertEmailResult.message, NotificationType.Success),
    Set(varCertError, varCertEmailResult.message); Notify("Could not email certificate - see the error below.", NotificationType.Error)
)

Update lblCurrentCertInfo.Text

This label currently checks varRecord.Attachments. After cutover, it should not depend on list attachments.

Power Fx - lblCurrentCertInfo.Text
=If(
    !IsBlank(varRecord) && !IsBlank(varRecord.DateCompleted),
    "Certificate metadata saved. Use Email certificate to request the file. Attach a new file below to replace it.",
    "No certificate on file yet."
)

Optional: Keep The Old Attachment UI Hidden, Not Deleted

Do not delete the old attachments from TT TrainingRecords during the first cutover. Leave them in place as a fallback until the new library has been used successfully for a while. The app will stop reading them once you update the formulas above.

8. Migrating Existing Attachments Later

This is deliberately not part of the first test. Once the new path works, existing certificates can be copied from TT TrainingRecords attachments into TT Certificates_LTD / TT Certificates (LTD) with a separate one-time admin flow:

  1. List rows from TT TrainingRecords.
  2. For each row, get attachments.
  3. For each attachment, get attachment content.
  4. Create file in TT Certificates_LTD / TT Certificates (LTD).
  5. Update file properties using the row's ID, person email, course ID, course name, date completed, and upload fields.

Do that only after the new save/email path is proven. Until then, old attachments can stay where they are.

9. Final Lockdown Checklist

  1. New library TT Certificates_LTD exists with exact columns, optionally renamed for display as TT Certificates (LTD).
  2. TT - Save Certificate Library TEST saves one file and fills metadata.
  3. TT - Email Certificate Library TEST emails that file to the authorised user.
  4. Unauthorised user test fails with the expected message.
  5. Live btnSaveCert calls the final library save flow.
  6. Live btnOpenCertificate is now Email certificate and calls the final email flow.
  7. lblCurrentCertInfo no longer checks varRecord.Attachments.
  8. Normal app users are removed from direct access to TT Certificates_LTD / TT Certificates (LTD).
  9. Normal app users still have whatever access they need to the metadata lists for the app to run.
  10. Old list attachments are retained until you are happy with the new route.

10. Sources And Assumptions

  • Power Apps UI is not a security layer over SharePoint data-source permissions. Microsoft reference: Connecting and authenticating to data sources.
  • Run-only flow users and flow-owner connections are the basis for using Power Automate as a controlled gate. Microsoft references: Share a cloud flow and Guide to cloud flow sharing and permissions.
  • This guide assumes the flow's SharePoint actions run through an account that is allowed to read and write TT Certificates_LTD / TT Certificates (LTD).
