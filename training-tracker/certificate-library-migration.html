Move Certificates Out Of TT TrainingRecords Attachments

This is the separate fix guide for moving certificates into a locked SharePoint document library while leaving the training tracker metadata in the existing lists. Follow the test phase first. Do not remove old attachments, flows, or formulas until the new save and email flows work against one real test record.

Answer to the big question: yes, you can test this in advance. Build the new TT Certificates_LTD library, optionally rename its display name to TT Certificates (LTD), and build the two new TEST flows first. Add two temporary buttons on scrCourseDetail to call those test flows. If the test works, then do the cutover edits. If it does not, delete the test buttons and the current app keeps using the old attachment route.

Permissions For Testing

For the first test, do not lock the library down yet. Give yourself and the flow owner access. Once the test flow works, change permissions like this:

  • Stop inheriting permissions on TT Certificates_LTD / TT Certificates (LTD).
  • Keep Full Control for the site owners/admins who are allowed to inspect certificates.
  • Keep access for the account whose SharePoint connection the flows use.
  • Remove normal app users from this library only. Do not remove their access from the metadata lists yet.

Use Text, not Date, for DateCompleted: a Date-typed trigger input demands strict ISO format (yyyy-mm-dd), but Power Apps serialises a Date value using the maker's locale display format instead (e.g. 06/08/2026), which fails validation with TriggerInputSchemaMismatch every time. Using Text here and building the ISO string explicitly on the Power Apps side (Text(datCompletion.SelectedDate, "yyyy-mm-dd")) sidesteps the mismatch entirely. Every SharePoint action below that consumes DateCompleted accepts a plain ISO text string into a Date column without any extra conversion.

5. Add Temporary Test Buttons In Power Apps

This is how you test without breaking the current working screen. Add the two test flows as data sources. Do not remove the old flows yet.

Temporary Save Test Button

Add a small temporary button to scrCourseDetail, or reuse an unused test button if you already have one. Set its Text to TEST save library and its OnSelect to this:

Power Fx - temporary save test
=Set(
    varSaveResult,
    'TT - Save Certificate Library TEST'.Run(
        Text(datCompletion.SelectedDate, "yyyy-mm-dd"),
        CountRows(colNewCertificate) > 0,
        If(CountRows(colNewCertificate) > 0, First(colNewCertificate).Name, ""),
        If(CountRows(colNewCertificate) > 0, {name: First(colNewCertificate).Name, contentBytes: First(colNewCertificate).Value}, Blank()),
        Lower(varRecord.PersonEmail),
        varCourse.CourseName,
        varMyEmail,
        varViewingForSelf,
        varRecord.ID,
        varCourse.CourseID,
        varIsAdmin
    )
);
If(
    varSaveResult.success,
    Notify("TEST save worked. Check TT Certificates (LTD).", NotificationType.Success),
    Notify(varSaveResult.message, NotificationType.Error)
)
If you get a red error "TriggerInputSchemaMismatch ... does not validate against format 'date'": your flow's DateCompleted trigger input is still typed Date. Go back to the flow's trigger and change it to Text (see the callout in section 2 above) — a Date-typed input will always fail this way, because Power Apps sends locale-formatted text (06/08/2026), never true ISO, no matter how the Date value is built on the app side. The code block above already sends the correct Text(datCompletion.SelectedDate, "yyyy-mm-dd") value; it only works once the trigger input itself is Text.
If you get "Missing column. Your formula is missing a column 'contentBytes' with a type of 'Blob'": the flow's FileContent trigger input needs a record with a column literally named contentBytes, not whatever field names the attachment control happens to use. Passing First(colNewCertificate) as-is (the old pattern from the original TT - Save Certificate flow) does not satisfy this. Build the record explicitly instead: {name: First(colNewCertificate).Name, contentBytes: First(colNewCertificate).Value}. The code block above already has this fix applied.

Safe Test Script

  1. Pick one training record you can safely test with.
  2. Open that record in scrCourseDetail.
  3. Select a small PDF or image certificate using the existing file picker.
  4. Click TEST save library.
  5. Open SharePoint TT Certificates_LTD / TT Certificates (LTD). Confirm one file exists for that TrainingRecordID and its metadata columns are filled.
  6. Click TEST email cert.
  7. Confirm the email arrives and the attachment opens.
  8. Run the test again with a different file. Confirm the library still has one current file for that TrainingRecordID, not duplicates.
Stop here if the test fails. Do not edit the live save/open buttons yet. The existing app can keep using the old list attachments while the new flows are fixed.

Optional: Keep The Old Attachment UI Hidden, Not Deleted

Do not delete the old attachments from TT TrainingRecords during the first cutover. Leave them in place as a fallback until the new library has been used successfully for a while. The app will stop reading them once you update the formulas above.

8. Migrating Existing Attachments Later

This is deliberately not part of the first test. Once the new path works, existing certificates can be copied from TT TrainingRecords attachments into TT Certificates_LTD / TT Certificates (LTD) with a separate one-time admin flow:

  1. List rows from TT TrainingRecords.
  2. For each row, get attachments.
  3. For each attachment, get attachment content.
  4. Create file in TT Certificates_LTD / TT Certificates (LTD).
  5. Update file properties using the row's ID, person email, course ID, course name, date completed, and upload fields.

Do that only after the new save/email path is proven. Until then, old attachments can stay where they are.

9. Final Lockdown Checklist

  1. New library TT Certificates_LTD exists with exact columns, optionally renamed for display as TT Certificates (LTD).
  2. TT - Save Certificate Library TEST saves one file and fills metadata.
  3. TT - Email Certificate Library TEST emails that file to the authorised user.
  4. Unauthorised user test fails with the expected message.
  5. Live btnSaveCert calls the final library save flow.
  6. Live btnOpenCertificate is now Email certificate and calls the final email flow.
  7. lblCurrentCertInfo no longer checks varRecord.Attachments.
  8. Normal app users are removed from direct access to TT Certificates_LTD / TT Certificates (LTD).
  9. Normal app users still have whatever access they need to the metadata lists for the app to run.
  10. Old list attachments are retained until you are happy with the new route.

10. Sources And Assumptions

  • Power Apps UI is not a security layer over SharePoint data-source permissions. Microsoft reference: Connecting and authenticating to data sources.
  • Run-only flow users and flow-owner connections are the basis for using Power Automate as a controlled gate. Microsoft references: Share a cloud flow and Guide to cloud flow sharing and permissions.
  • This guide assumes the flow's SharePoint actions run through an account that is allowed to read and write TT Certificates_LTD / TT Certificates (LTD).
