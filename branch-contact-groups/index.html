This Push - v2.38

Add three new columns to BM Memberships in SharePoint first (all Single line of text, Not Required):

ColumnPurpose
NameThe real field the app now reads/writes for a person's display name. Title stays only as a mirror for SharePoint's own list view - the app never reads Title again.
JMCBde/Area from the standard import sheet. Blank hides the field on cards.
County/ContingentCounty/District from the standard import sheet. Referenced in Power Fx as ThisItem.'County/Contingent' (quoted, because of the slash). Blank hides the field on cards.
For this push, add scrQuickContacts as a new screen. Existing scrSendEmail, scrManageGroups, and scrManagePeople are not replaced by this quick-card pass, because the local source is behind the latest Studio visual edits.
Backfill existing membership rows before testing v2.34. After adding the new Name column, existing rows will still have their old display name in Title and a blank Name. Copy each existing Title value into Name once (for example in SharePoint grid edit) before relying on Manage People, member popups, search, or name sorting.
New saved selections list: create BM Saved Selections and add it as a data source before pasting scrSendEmail v2.27. Columns: Title, SelectionName, and GroupName, all Single line of text and Not Required.

This push adds scrQuickContacts, a cleaner card-based quick-copy screen. It loads the same SharePoint-backed groups and memberships, hides private groups from non-maintainers, lets you search/filter contact lists, and copies one group's resolved email addresses straight to the clipboard from the card.

The previous Add existing Manage Groups feature is still available in scrManageGroups v2.24. Open a group, click the personnel icon, switch to Add existing, search the people already known to the app, tick multiple people, then click Add selected.

Full visual refresh note: the all-screen green-and-white visual pass should wait until the latest Studio/export YAML is available. The current local scrSendEmail source still has older UI details that you have already changed manually, so replacing all screens from it would undo those changes.

Also carried in the new scrManageGroups v2.24 YAML: the defensive drpEditThursdayBatch.Default formula below, and the in-app version label has been removed so it does not come back if you replace the screen.

Manual property fix: if drpEditThursdayBatch still opens blank instead of showing None, select drpEditThursdayBatch on scrManageGroups and replace its Default property with this formula.
drpEditThursdayBatch.Default
LookUp(
    colThursdayBatchOptions,
    Lower(Trim(Value)) =
        Lower(Trim(Coalesce(LookUp(colGroups, ID = varManageGroupID).ThursdayBatch.Value, "None")))
)

Still included from the previous polish pass: reusable saved send selections on Send Email; a read-only Admin Health Check in Manage Groups; add/remove/unchanged diff counts before paste-replacing a roster; manual Refresh and last-loaded labels on the data-heavy screens; a red "Delete group" button in Manage Groups; clear (X) buttons on search boxes; and cached GAL search results instead of live connector calls from gallery Items.

Paste-import in Manage Groups now recognises the standard sheet automatically: Bde/Area→JMC, County/District→County/Contingent, Rank + First Name (Proper Case) + Surname (UPPERCASE)→Name, Appointment ignored, Email→Email. The old 2-column Name/Email paste still works for groups without this structured data.
